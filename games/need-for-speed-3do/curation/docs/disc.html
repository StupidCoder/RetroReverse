3DO discs don't use ISO 9660. The 846 files here sit in the Opera file system: every field big-endian (the console's ARM60 runs big-endian), the volume label at block 0 rather than ISO's block 16, and every file present as one or more identical copies — avatars — scattered across the disc to cut seek time. A directory entry lists all its avatar block numbers; bulk file data pools near the front of the disc while the directory tree sits a couple of hundred thousand blocks away at the back, so the laser rarely travels far for content.

The boot chain

LaunchMe (290 KB) is a textbook big-endian ARM Image Format executable: a four-instruction header that self-relocates, zero-fills its BSS and jumps to the entry point. It carries the race engine, the physics, the AI and the static track tables. The front-end menus live in a second AIF, frontovl, loaded as an overlay module: the loader runs the overlay's own header in place, then hands it a table of engine function pointers — the overlay calls back into LaunchMe for memory, files and drawing. System/ holds Portfolio OS itself — kernel, folios and 32 programs, all AIF ARM60 code like the game.

DriveData: cars as data, physics as text

Everything a car is lives under DriveData/CarData, keyed by a four-letter tag (LDIA, ANSX, COP1, …): the 3D model and its textures in a .WrapFam, the dashboard art in a .dashFam, tyre sprites in .TireF/R — and the entire physics setup in plain readable text. A .TdDyn file spells out #Mass, #MomentOfInertia, per-gear top speeds, the redline and a 100-sample power curve; the difficulty system is two more numbers per skill level in the same files. The cars were tuned in a text editor.

The movies

Each Movies/*.Stream is a flat chunk stream for the SDK's DataStreamer: FILM video subchunks interleaved with SNDS audio. The video is Cinepak at 15 fps, 320×240 — the 3DO has no video-decode hardware, so the ARM60 decodes every frame in software while a DSP instrument plays the SDX2 audio. The intro, the attract reel and the showcase clips — 165 streams in all — ride this one player.

Time comes from the audio folio

One quirk ties the whole engine together: the race loop does not pace itself on the video beam. Each frame it asks the audio folio's 240 Hz clock to wake it — SignalAtTime(cue, GetAudioTime() + 4), and four audio ticks are exactly one 60 Hz field — then sleeps on the cue's signal. The frame clock lives in the same time domain the music and effects engine syncs to. Around it, the per-frame work — streaming track chunks in, running the drivers, building the display list — runs as cooperating Portfolio tasks passing kernel signals, closer to a small operating system than a bare-metal game loop.
