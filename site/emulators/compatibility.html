What these emulators support

These are educational, experimental emulators. You can select an unfamiliar image, but that does not guarantee it will boot or render correctly. Game files stay on your computer. The site downloads emulator code, artwork and C64 firmware.

Firmware and disc layouts

C64 BASIC, KERNAL and character ROMs are hosted here and hash-checked. You can override all three with local files. PS1 and 3DO use incomplete BIOS/OS high-level emulation; no local BIOS file is requested. C64 disk images, combined data/audio BIN files and CUE pregaps/postgaps are unsupported. Audio tracks are not played. Select a CUE together with the files it names.

Inspecting a frame

Pause records one complete declared display interval. C64 uses its raster frame; PS1 and N64 currently use synthetic timing boundaries; PS1 captures four fields to include double-buffer producer context; 3DO uses DisplayScreen calls. Select a pixel to see observed writes and sources. The rendering slider replays captured effects in separate scratch memory. It does not advance the paused machine.

Pre-existing framebuffer contents and missing history are labeled. PS1 semi-transparency and mask-bit effects are incomplete. N64 coverage and scanout are simplified, and texture evidence identifies the last filter tap. 3DO source bytes and PIXC results are recorded without claiming universal instruction-level dataflow. Replay uses the final display-buffer mapping.

States and controls

States require the same game files, firmware, compatibility settings and exact core build. Select the original media after reloading the page, then load the state. A rejected state leaves the current machine intact. States download locally; they are not cloud saves. Keyboard, on-screen buttons and standard gamepad mappings are available. Controls release when focus is lost.

Browser validation

Browser workflows have been exercised in Chromium. Safari has passed the hosted C64 firmware, state-import, capture and replay checks. Firefox, the remaining Safari/game combinations and a physical gamepad session still need end-to-end acceptance. Native and Node/WASM tests are reported separately and do not establish browser compatibility. File selection, WebAssembly, module workers and synchronous worker-local File reads are required. Sound output is not part of this release.

Performance counters distinguish emulated progress from frames actually presented. Normal mode aims for native timing; fast-forward removes that pacing. Detailed capture and replay costs are reported separately.
