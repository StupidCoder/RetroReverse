The main program and the track loader are stored encrypted — at full size, no compression; the near-random 7.95 bits/byte is cipher, not packing. The decryptor, c/zzz, is a drop-in LoadSeg replacement: it walks the standard Amiga hunk format, but XORs every payload longword with a keystream.

Selective encryption

The encryption is deliberately partial. Hunk structure markers — HUNK_HEADER, CODE, DATA, RELOC32 — and even the symbol names are stored in plaintext, so _AllocMem and _FindTask sit as readable ASCII inside the “encrypted” file while the code bodies around them scramble. The keystream is an additive lagged-Fibonacci generator over a 55-entry table seeded from the constant $57319753 by a ×31 hash.

The key is machine state

Before decrypting, the key table is perturbed with bytes from two pieces of the running machine: the CPU exception and TRAP vectors in low memory, and two handler pointers read out of the launcher's own task structure. On a Kickstart 1.x machine every one of those vectors points into the ROM at $FC0000, so the extracted byte is uniformly $FC — the decryption key is the ROM page. Kickstart 2.0 moved the ROM to $F80000, which is why a game like this is Kickstart-version-locked: on a newer machine the key changes and the program decrypts to garbage. The task-structure fields are the sharper teeth — they only exist once AmigaDOS has actually constructed the process, so no amount of reading the disk alone can produce them.

The key that keys the key

The main program's pass adds a 20-longword key array — and the track loader builds it itself at run time, as datalen / ((i+1) × 300), before the launcher XORs every entry with the 16-bit integrity checksum of the loader's own code. The entire remaining secret of a 175 KB encrypted program is thus one 16-bit constant ($CDDA) — small enough to find by trying all 65,536 values against a does-this-decode-to-a-valid-hunk-file test.
